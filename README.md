# 歌单批量下载助手 v2.4 · 可见浏览器自动适配

Windows 桌面程序：导入 TXT / CSV 歌单，扫描本地音乐，双重去重，然后**自动打开可见浏览器，在网页上输入、搜索、选择匹配歌曲并点击下载按钮**，最后校验浏览器产生的文件。

## 使用

支持 Windows 10/11 x64。EXE 不包含 Chromium 浏览器，也不会自动下载或安装浏览器。

从 GitHub Releases 直接下载 **`PlaylistBatchAssistant.exe`**，双击运行，无需解压或配套文件夹。不需要安装 Python 或浏览器插件；电脑需已安装 **Chrome 或 Edge**。程序使用独立浏览器资料目录，不接管日常浏览器标签。单文件 EXE 首次启动需要解包运行组件，可能稍有等待。

默认“自动”依次尝试已安装的 **Microsoft Edge → Google Chrome**；不同电脑可能使用不同浏览器，也可在界面指定。启动日志显示尝试过程，界面显示实际启动的浏览器。如果两者均无法启动，下载停止、任务保留待处理，并显示安装与排错提示。安装 [Edge](https://www.microsoft.com/edge) 或 [Chrome](https://www.google.com/chrome/) 后重新开始即可；本地扫描和歌单编辑仍可使用。需要联网访问音乐网站。

1. **导入歌单**：支持多个 TXT / CSV；TXT 格式是 `歌名 - 歌手`，PlaylistOut 格式为 `歌名 - 歌手 - 专辑`；CSV 至少有 `title,artist` 或 `歌名,歌手` 两列。导入、从 TXT 重新同步、编辑保存后自动扫描本地目录，先将已有歌曲标为“本地已有”，这一阶段不会打开网页或下载。
2. **自动识别**：识别 Windows 的音乐、下载目录（包括系统重定向目录）。其他磁盘或自定义文件夹，用 **选择目录** 多次添加。不会自动遍历所有硬盘。
3. **选择下载目录**，点 **重新扫描**。下载目录始终参与去重；本地文件优先读取音频标签，无标签时识别 `歌名 - 歌手` 和 `歌手 - 歌名` 文件名。
4. 勾选需要的音源，点 **开始网页自动下载**。浏览器自动出现；能看到文字逐字输入、音源切换、Get 搜索、候选选择和下载按钮点击。按界面从左至右尝试已选音源，每个音源默认只搜一次；精确匹配后立即停止搜索其他音源。
5. 可以 **暂停 / 继续**、**跳过**、**停止**，或点 **显示自动浏览器**把正在操作的同一个窗口带到前台。**不需要手动打开页面、输入或点下载**。请不要在执行期间手动切换这个专用窗口里的歌曲。
6. 下方运行日志显示每一步、等待时间、网站提示和失败原因；点击 **重试失败 / 待确认** 会把失败、待确认和手动跳过项重新排队。

原项目的 `playlists` 文件夹保留在本地，可直接从中导入；仓库与发行包不包含个人歌单、歌曲或登录凭据。

## 音源显示与修改

- **启用音源**：勾选网易、QQ、酷狗、酷我、咪咕中的任意组合。默认全选。
- **查找失败后二次搜索**：各音源独立勾选，默认全部关闭。只有第一轮所有所选音源均未精确匹配，才对勾选的音源用“仅歌名”再搜一次。
- **按 TXT 文件名识别音源**：例如 `网易收藏.txt`、`QQ歌单.txt`；未识别时使用全局勾选。支持网易/QQ/酷狗/酷我/咪咕及对应英文名。
- 列表的 **音源 / 策略** 列显示每首歌将使用的音源。选中歌曲，在 **所选歌曲音源** 下拉框点击修改；选择“自动（按规则）”恢复自动策略。运行时显示 **当前音源及搜索轮次**。
- 优先级：**单首手动指定 > 文件名识别 > 全局勾选**。设置自动保存。修改失败/待确认歌曲的音源会将其重新排队；运行期间需先停止才能修改。
- 找到精确匹配后，不再搜索其他音源；当前候选重试仍返回无效音频时，可尝试本次搜索结果里的下一个精确匹配候选。歌名、完整歌手与版本仍需一致，不下载近似或不同版本。所有精确候选均失败才将失败原因保留在列表，可手动换源重试。
- 下载返回文本错误或无效音频时，等待 3 秒、6 秒重试同一候选的下载，最多重试 2 次。成功立即停止；这与第二轮“搜索”独立，不重新遍历其他音源。禁用浏览器 HTTP 缓存，避免重复使用已缓存的错误响应。
- 专用浏览器处于下载模式：禁止预览自动播放、媒体错误/播放结束引起的自动跳歌；点击下载前再次核对当前歌名歌手。网页候选点击与下载按钮仍由程序可见操作。

## TXT 歌单增删改查

点 **管理 TXT 歌单**，打开 `playlists` 中的 TXT 或新建 TXT，可按歌名/歌手查找、新增、修改和删除歌曲。点击 **保存 TXT 并同步任务** 后写回文件，并自动更新下载任务。也可用文本编辑器修改文件，再点 **从 TXT 重新同步**。

未改动歌曲保留任务状态与手动音源；新歌、改名或改歌手的歌曲重新排队；从所有已导入歌单删除的歌曲移除任务。删除任务不会删除本地音乐。保存前自动产生 `.before-edit-*.bak`，保留原文件编码、换行、专辑与标记；如果 TXT 被外部修改，拒绝覆盖并提示重新打开。TXT 的歌曲行格式仍是 `歌名 - 歌手`（可加 ` - 专辑`）；音源设置保存在会话中。

## 匹配与去重

- 歌单内统一大小写、全角半角、标点和多歌手顺序后去重。
- Live/现场、Remix/混音、伴奏、Acoustic、不插电、Demo、Cover、Remaster 和速度/音调标记保持区别。不同演出副标题和不同 Remix 名称保留。
- 歌名与歌手的相似度分别展示。**自动下载要求归一化后的歌名、完整歌手集合与版本一致**；近似但不一致的候选进入“待确认”，避免同名翻唱、Live/录音室版本混淆。
- 本地已有文件须通过音频检查才跳过。成功下载会立刻更新本轮索引；下次运行重新扫描，不盲信上次的“成功”状态。
- 无法从标签或文件名可靠识别的文件不会被武断判为已存在；特殊歌手别名、繁简差异和没有清晰分隔符的文件名可能需要手动核对。

## 文件去重 / 删除重复

点击本地音乐设置中的 **文件去重 / 删除重复**，选择音乐目录并扫描。界面列出“保留文件”和“将删除”完整路径。仅对有效音频按大小、完整 SHA-256 判断重复；删除前重新计算哈希并逐字节复核。每组优先保留文件名较短的一份。

**注意：确认删除会永久删除清单中的副本，不进入回收站。** 界面和确认框均显示此提示。不同编码、音质、标签或版本造成的不同文件，不会只凭同名而删除；扫描后内容变化或目录外的文件拒绝删除。清单保存在程序会话目录的 `duplicates-*.jsonl`，清理后关闭窗口会重新扫描本地歌曲。

## 下载文件成功的判定

默认最小 **256 KiB**（界面可调）、时长至少 **90 秒**（固定规则，90 秒整可保留）。接收网页点击触发的浏览器下载，保存到随机 `.part` 文件，然后检查：

- 浏览器下载是否完成、文件大小是否在允许范围（最多 512 MiB）；
- 文件内容是否是 HTML、JSON 或其他文本错误页；
- 真实文件头、对应音频扩展名，以及 Mutagen 能否解析有效音频时长；
- WAV 声明长度是否完整。

校验通过后才将临时文件原子发布为正式文件并记录“成功”。扩展名由内容识别，网站误写 `.mp3` 的 FLAC 会保存为 `.flac`。同名文件不会覆盖；失败/取消清理本次临时文件。

搜索结果提供可靠时长且不足 90 秒时直接跳过该候选。网站没有提供时长时，需要临时接收文件后解析；不足 90 秒的临时文件会删除，不保存为正式歌曲，也不反复重试同一短片段。可继续尝试同次结果中的其他精确候选；未获得合格音频时标记 **时长不足**，统计栏单独计数。普通重试失败操作不重新排队这些短片段。

点 **删除短音频（<90秒）** 可扫描所选目录，预览实测时长与文件路径，确认后永久删除。删除前复核文件哈希和实际时长；90 秒整及以上、损坏或无法确认时长的文件保留。清单写到 `%LOCALAPPDATA%\PlaylistBatchAssistant\short-audio-*.jsonl`；下次载入或同步歌单也会标记已删除的短音频，避免作为缺失歌曲自动重新下载。已有合格长音频会在重新扫描时标为本地已有。

网站使用 fetch/Blob 生成下载，因此浏览器下载事件不会保留源响应的 HTTP 状态、Content-Length 或 MIME；本模式以实际文件内容校验为准。大小上限在浏览器生成文件后检查，不能限制网站脚本下载到内存的流量。文件校验不能证明音源标注一定正确，也不是逐帧解码检测；达到 90 秒也不能证明一定为完整版。

## 队列与保存

每次状态变化自动保存到 `%LOCALAPPDATA%\PlaylistBatchAssistant\session.json`。扫描异常在同目录 `scan_warnings.txt`，逐步操作日志在 `runtime.log`。每轮使用临时独立浏览器配置，结束并关闭浏览器后清理，不复用旧的 `browser-profile`；网站登录状态不会跨轮保存，歌单/音源设置/下载进度仍保存在程序会话中。也可手动保存会话或导出 CSV 日志。兼容原 v1 会话的歌曲字段；运行中的项目恢复为待处理。

如果浏览器在保存下载时关闭或崩溃，整批停止，当前歌曲保留为“待处理”，不会误标歌曲失败或继续搜索下一首。日志记录页面关闭、崩溃、会话关闭与连接断开事件。重新点击开始即可重试；加载旧会话时，曾因 `Target page, context or browser has been closed` 失败的歌曲也会恢复待处理。

扫描和浏览器操作在工作线程执行，界面保持响应。暂停/停止/跳过在网页操作之间与等待轮询中生效；正在执行的导航最多等待 30 秒。页面结果等待 30 秒、浏览器下载事件等待 90 秒，期间每 5 秒报告状态。网站 Blob 已形成后保存下载文件可能额外等待浏览器完成。暂停时间不计入页面轮询超时。每轮搜索至少间隔 2 秒。浏览器启动失败、被关闭或页面脚本错误会停止本轮，避免把整张歌单批量误标失败。任务结束保留浏览器供核对，停止或关闭程序时关闭。

## 真实网站验证（2026-09-20）

v2.1 已在可见 Chrome 上实测：自动输入“寓言 张韶涵”、点击 Get、读取 10 条网页候选、点击准确候选，再点击网页的下载按钮。自动化读取页面中的歌名、歌手并在点击下载前再次核对。程序不通过后台接口替代网页操作。

早先《寓言》返回过脚本加“获取失败”文字，已被校验拒绝。v2.2.1 排查时，在原有专用浏览器配置中复现 Chrome 下载崩溃（退出码 `0xC0000005`）；使用每轮全新配置后，同一 QQ 候选成功保存为有效 MP3（约 9.4 MiB，246.8 秒）。这验证了一首真实歌曲的成功下载，不代表所有音源或歌曲均可用；仍以预发布版交付。

v2.3 进一步复现：同次 QQ 搜索《New Boy》时，第一个精确候选返回“获取失败”，另一个精确候选可下载有效音频。因此下载无效后保留音频校验，有限重试并使用同次结果中的其他精确候选；不会把错误文本放行。部分歌曲即使重试仍返回错误内容，不保证网站每个候选可用。

程序不解密 DRM、不处理验证码、不绕过登录/付费限制；仅处理网站正常返回的下载地址。请用于你有权保存的音频。

Python **3.12+**（本次验证使用 3.13）:

```powershell
python -m pip install -r requirements.txt
python app.py
```

```powershell

```


## 模块

`playlist_parser.py` 歌单解析；`playlist_document.py` TXT 编辑与任务同步；`playlist_editor.py` 编辑窗口；`source_policy.py` 音源与重试策略；`matching.py` 匹配；`audio_files.py` 本地扫描和校验；`browser_provider.py` 可见浏览器操作；`downloader.py` 文件发布及旧接口下载；`engine.py` 队列；`app.py` 桌面界面；`selftest.py` / `policy_selftest.py` 回归；`browser_selftest.py` 真实浏览器集成测试。`provider.py` 仅保留供旧接口回归，GUI 默认使用可见浏览器。
